# 開発のしかた

## 作品を書く Claude Code は、実データを開かない

- この作品のコードを書く Claude Code は、作者のふだんの設定とは別の設定のフォルダで起動している。
- その設定は次の2つを拒否する。
  - 読み取りの道具で、実データのフォルダ・試用の記録のフォルダ・学校の同期フォルダ・`.env` を読むこと
  - それらのパスを含むコマンド（Bash・PowerShell）
- 本物の設定はリポジトリの外にある。ここに置いた [claude-code-settings.example.json](claude-code-settings.example.json) は、場所を置き換えた写し。
  - `<EBINO_DATA_DIR>` は実データのフォルダ、`<EBINO_RECORDS_DIR>` は記録のフォルダ。作品はこの2つを環境変数から読む。
  - `<学校の同期フォルダ>` は、学校のファイルが同期されるフォルダ。
  - モデルは Opus で、effort は high。
- Claude Code は、架空の見本データ（`samples/`）とテストで作る。

## 実データでの実行は、別の Claude Code が受け持つ

- 実データでの実行は、作者の側の別の Claude Code が受け持つ。
- 作品を書く Claude Code に返すのは、件数と、中身を伏せた形（理由のコード・ID）だけ。
- 実データでだけ出る失敗は、この返ってきた形をもとに直す。

## 製品の中の係ごとのモデル

`ebino/gate.py` の `MODELS` と `EFFORT` のとおり。どの係でも、断られたときや失敗したときに別のモデルが代わりに答えることはない（決まった文を出す）。

| 係（コードの名前） | モデル | effort | 選んだ理由 |
|---|---|---|---|
| 取り込み係（`tagger`） | claude-haiku-5-5 | low | 片ごとに話題の札と語りの種類を付けて分けるだけで、文は書かせない。片の数が多い。 |
| 司書（`librarian`） | claude-sonnet-5-5 | medium | 問いに合う片を、道具（人・場所・話題で絞る）を何回か呼んで探しに行く。道具の使い方の判断は要るが、最後にどの片を使うかは司会が選ぶので、Opus までは使わない。 |
| 司会（`moderator`） | claude-opus-5-5 | high | 何十人分もの言葉を横に読んで、どの席にどの順で話させるかを選び、割れたところに見出しを立てる重い判断。席に聞く札と最後の一言で片を選ぶのも、この係。 |
| ふりかえり（`reflection`） | claude-opus-5-5 | high | 司会の仕事。その子の記録を丸ごと読み、材料を1つ指して問いを返し、方向の違う次の一手の案を並べる。 |
| 編集者（`editor`） | claude-sonnet-5-5 | low | 質問カードの言い換え案と、長いポスターの目的の見本の要約を書く。文を書く係なので Sonnet。書く文は短く、コードの照合を通ったものだけ残すので、effort は low。 |
| 収穫カード③（`subjects`） | claude-haiku-5-5 | low | 記録を札1つと項目の番号2つに分けるだけで、文は書かせない。 |
